# Спека: согласование и выполнение заявок на продление

Источник: `Fullstack_практическое_задание.pdf` (в репозиторий не кладётся), макет `reference_renewals.png`, имитатор `provider_simulator.py`.

Срок сдачи: до конца 2026-11-13. Первый день 2026-11-10.

## Что делаем

Веб-приложение: сотрудник создаёт заявку на продление ресурса на 30 дней, другой сотрудник одобряет или отклоняет, после одобрения фоновый обработчик отправляет операцию тестовому провайдеру и после подтверждения сдвигает срок ресурса ровно один раз.

Стек: TypeScript, React, NestJS, PostgreSQL.

## Данные

Пространства: Alpha, Beta. Ресурсы:

| ID | Пространство | Название | Срок | Стоимость |
|---|---|---|---|---|
| res-a-01 | Alpha | Хранилище A | 2027-03-01 | 128000 коп., RUB |
| res-a-02 | Alpha | Сервис B | 2027-05-20 | 250000 коп., RUB |
| res-b-01 | Beta | Сервис C | 2027-06-01 | 150000 коп., RUB |

Стоимость хранится целым числом копеек, срок календарной датой без времени.

Учётные записи:

| Пользователь | Пространство | Права |
|---|---|---|
| Инициатор Alpha | Alpha | просмотр, создание заявки |
| Согласующий Alpha | Alpha | просмотр, одобрение и отклонение |
| Инициатор Beta | Beta | просмотр, создание заявки |
| Универсальный Alpha | Alpha | обе роли, свою заявку согласовать нельзя |

## Правила доступа

- Пользователя и права сервер берёт из учётной записи, не из полей запроса.
- Нет авторизации: 401. Нет доступа к пространству или действию: 403.
- Пользователь одного пространства не читает и не меняет данные другого, в том числе по известному ID.

## Состояния заявки

| Состояние | Код | Как попадает |
|---|---|---|
| На согласовании | `pending` | создана инициатором |
| Отклонена | `rejected` | отклонил согласующий, провайдер не вызывается, ресурс не меняется |
| Выполняется | `processing` | одобрена, задача отправки сохранена |
| Завершена | `completed` | провайдер подтвердил, срок сдвинут один раз |
| Требует внимания | `needs_attention` | нет подтверждения после трёх попыток POST |

Переходы: `pending -> processing`, `pending -> rejected`, `processing -> completed`, `processing -> needs_attention`, `needs_attention -> processing` (повтор согласующим, тот же ключ), `needs_attention -> completed` невозможен напрямую, только через повтор.

## Бизнес-правила

- Продление всегда 30 календарных дней от текущего срока ресурса. Сумма, прежняя и новая даты фиксируются в заявке при создании.
- Свою заявку нельзя ни одобрить, ни отклонить.
- У ресурса не больше одной активной заявки (`pending`, `processing`, `needs_attention`). Закреплено в базе.
- Повторное согласование и недопустимый переход: 409.
- При одобрении срок и стоимость ресурса сверяются со снимком в заявке. Не совпали: 409, провайдер не вызывается.
- История: автор, время, переход. Секреты и полный ответ провайдера в логи не пишутся.

## Надёжность

- Одобрение и постановка задачи отправки сохраняются одной транзакцией.
- На 503 результат неизвестен: повтор с тем же ключом и телом либо проверка GET. У имитатора остаётся одна операция.
- Подтверждение провайдера, состояние заявки и новый срок пишутся одной транзакцией. Повторная обработка срок не сдвигает.
- Параллельное одобрение: один успех, второй 409, одна задача.
- Три попытки POST без результата: «Требует внимания». GET попыткой не считается. Согласующий может повторить с тем же ключом. До разрешения новая заявка на ресурс недоступна.
- Задержка после 503 настраивается, чтобы успеть остановить приложение. После перезапуска приложение получает прежний результат и завершает заявку.

## Контрольный сценарий приёмки

Имитатор свежезапущен и не перезапускается.

1. Инициатор Alpha создаёт заявку на res-a-01: `pending`, срок ресурса прежний. Вторая активная заявка отклоняется.
2. Инициатор Beta не получает ресурс и заявку Alpha по ID. Универсальный не может согласовать свою заявку.
3. Согласующий Alpha одобряет. Два параллельных одобрения дают одну задачу, повторное одобрение 409.
4. Первая отправка даёт 503. Приложение останавливается и запускается, восстанавливает задачу, использует тот же ключ, получает сохранённый результат.
5. Заявка `completed`, срок 2027-03-31. Повторная обработка дату не меняет. GET по ключу: `started_count=1`. `GET /stats?resource_id=res-a-01`: `operation_count=1`.
6. Отклонённая заявка провайдеру не уходит и срок не меняет. Статистика другого ресурса 0. Ошибки и результаты видны в интерфейсе и истории.
