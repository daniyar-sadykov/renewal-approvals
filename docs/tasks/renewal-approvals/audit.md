### Мелочи

**М1. Отличия от макета (стр. 6).** На 1440x900: сумма показана как «1 280,00 ₽», на макете «1 280,00 RUB»; значок статуса 13px жирным в рамке, на макете обычный цветной текст, а требование «текст 14-16px»; заголовки карточек 20px; вместо одной кнопки «Создать заявку» кнопка «Продлить на 30 дней» в каждой строке; две карточки (ресурсы и заявки) вместо одной. Замерено через `getComputedStyle` в браузере. Задание оценивает близость без попиксельного сравнения.

**М2. README не описывает перезапуск имитатора посреди обработки.** Воспроизведение: одобрить заявку, после 503 перезапустить имитатор, ждать. Наблюдение через прокси: `POST -> 503`, после перезапуска `GET -> 404`, `POST -> 503`, `GET -> 200`, заявка `completed`, срок сдвинут один раз, `post_attempts=2`. У прежнего экземпляра имитатора операция была создана, у нового создана ещё одна тем же ключом. В README сказано только, что данные имитатора пропадают при перезапуске.

**М3. `apps/api/test/health.spec.ts` поднимает приложение с настоящим конфигом.** Строка 13: модуль собирается без подмены `APP_CONFIG`, то есть с включённым обработчиком и адресом провайдера `127.0.0.1:8091`. Остальные тесты выключают обработчик через `createTestApp`. Если в тестовой базе остались задачи `queued` от предыдущего файла, обработчик этого теста пойдёт с ними к порту 8091. В двух моих прогонах подряд это ничего не сломало.

**М4. Пустые утверждения в `07-snapshot-check.spec.ts`.** Строки 62-63: «Провайдер не вызван: у имитатора нет операций». Приложение в этом файле создаётся без обработчика (`createTestApp()` в строке 22), поэтому утверждение проходит при любом коде. Реально отсутствие отправки доказывает только `jobs: 0` строкой выше. При поломке сверки со снимком тест всё равно падает (проверено мутацией).

**М5. Автотесты не покрывают то, что я проверял руками:** плюс 30 дней через границу года и февраль (в тестах только 01.03, 20.05, 01.06); запуск в другом часовом поясе; содержимое логов; подмену роли через заголовки на действиях с заявкой (заголовки проверены только на `/api/auth/me`); «ровно три POST» на настоящем имитаторе (только заглушка, причина объяснена в README). **М7. README расходится с кодом в двух местах.** README, раздел ограничений: «Для `resource_changed` интерфейс об этом предупреждает». В том же файле (строки 76-79) 408 и 429 названы «временными, их можно повторить», а сервер любой 4xx сразу переводит в «Требует внимания» (`provider.client.ts:88`).

- после 503 до следующего запроса: после запуска только GET;
- посреди первого POST (имитатор операцию сохранил, приложение ответа не получило): после запуска только GET, нового POST нет;
- посреди подтверждающего GET, перед записью результата: после запуска ещё один GET, срок сдвинут один раз.

**Два экземпляра на одной базе** (порты 3000 и 3001, 6 кругов по 2 ресурса, одобрения параллельно через оба): 12 заявок `completed`, по одному POST на ключ, 12 разных операций, сроки сдвинуты ровно на 180 дней, событий `completed` по одному на заявку. Работали оба экземпляра (9 и 3 завершения).
